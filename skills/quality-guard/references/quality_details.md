# ISO9001:2015 品質管理・PDCA詳細

「証拠に基づき、正しく・安全に・持続的に動くシステムを提供する」

## リスク判定マトリクス (G1 ゲート)
- 🟢 **通常**: テスト追加・ドキュメント修正。即着手可。
- 🟡 **標準**: 既存コード修正。`git commit` で現状保存後に着手。
- 🟠 **強化**: API変更・複数機能に影響。影響分析後に着手。
- 🔴 **最高**: DB変更・デプロイ。作業用 Worktree の作成を推奨。

## PDCAゲート詳細
- **Plan**: `quality/risks.md` で影響範囲を記録。
- **Do**: TDD で実装。
- **Check**: 3層検証（Unit -> E2E -> 本番相当）。デプロイ前に E2E 通過必須。
- **Act**: 不適合（テスト・ビルド失敗）発生時は `tasks/` に記録して是正・水平展開します。コード・ファイル編集および不適合の是正・修正に際しては、専門スキル `hypothesis-driven-editor` を適用し、その物理的仮説ログゲートと段階的アプローチ（Low to High）を徹底します。

# 5S プロトコル & リソース監視（物理コマンド検証）

異常事態の検知と対策は、お題目としての閾値設定ではなく、**「大規模処理の前後で必ず物理監視コマンドを実行し、結果をログに証拠（Evidence）として記録する」**という行動によって実効性を担保します。

## 1. 物理監視コマンドの実行
データ処理、大規模テスト、ビルドの前後で必ず以下のコマンドを pwsh で実行し、結果を思考プロセスまたはログに記載してください。
- **CPU負荷の監視**:
  `Get-Process | Sort-Object CPU -Descending | Select-Object -First 5`
  (CPUリソースを著しく消費している上位5プロセスを特定し、AIプロセス自体のハングやループを検知します)
- **メモリ空き容量の監視**:
  `Get-Counter '\Memory\Available MBytes'`
  (空きメモリが著しく減少していないかを確認し、メモリリークを未然に防ぎます)

## 2. 異常事態（異常値）の定義と是正アクション
- **CPU**: 50% 以上が持続、またはAIのスレッドがハングアップ。
  *アクション*: `manage_task` でプロセスを特定し、直ちに強制終了（`kill`）の上、アプローチの最適化（例：Polars Lazyの適用によるクエリ最適化）を行います。
- **メモリ**: 空きメモリが100MB以下、または利用率が 90% を超過。
  *アクション*: 一時オブジェクトの削除や、データの小分け処理（チャンク処理）に即座に設計を切り替えます。

## 3. 5S (整理・整頓・清掃・清潔・躾) の物理的完了基準
- **整理・整頓**: タスク開始前に必ず `git status` を実行し、未追跡のファイルを `git clean -fd` または `Remove-Item` でクリーンアップし、環境を「クリーンな基準状態」に整えます。
- **清掃・清潔**: タスク完了直前に、自ら作成したデバッグ用コード（`test_xxx.py` 等のゴミ）、一時的なダミーデータ、ログファイルを `Remove-Item -Force` で物理削除し、作業ツリーに不適合ゴミを一切残存させない状態でユーザーに報告します。

# 知識ベース自動参照（オンデマンドGrep）

知識ベースの「ただのロード」はコンテキストを無駄に浪費するため、タスク開始時に `grep_search` を用いて、関連するカテゴリ（`ipa/`, `stats/`, `python3/` 等）から必要な知識のみをピンポイントで Grep & Read することを義務付けます。
- 🛡️ **安全 (Security)** / ⚡ **性能 (Performance)** / ✅ **テスト (Test)** の観点は全タスクで横断チェックを行います。
