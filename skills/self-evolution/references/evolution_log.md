# Self-Evolution Log (自己進化ログ履歴)

本ファイルは、不適合の発生やユーザーからのフィードバックを契機に、エージェント自身が自己のスキル構成をアップデート（進化）させた際の「物理的な履歴記録」です。
お題目や標語（〜に注意する、など）による反省は一切禁止し、常に「どのような物理ゲートや機械的ルールを搭載したか」の設計事実のみを論理的に蓄積します。

---

## 【自己進化記録テンプレート（新規追加時にコピーして使用）】

```markdown
## [進化記録] YYYY/MM/DD: （タスク名・不適合名）

- **現象と原因**: （どのようなエラーや不具合が発生し、その真の根本原因は何だったか）
- **解決策となぜそうしたか**: （どのように解決し、なぜその解決策が最善だったのかの論理的根拠）
- **機械的ルールへの落とし込み (No-Slogan)**: （『〜に注意する』等の標語を完全に禁止し、『〇〇の前に△△ファイルを物理作成する』『1関数30行制限』といった、AIが解釈の余地を持てない【物理ゲート】や【静的・機械的ルール】に変換した内容）
```

## 自己進化履歴

### [進化記録] 2026/06/17: Claude由来「fix-guard」のお題目形骸化対策と「物理的自己制御スキル群」への完全脱皮

- **現象と原因**:
  - Claude由来の `fix-guard` というお題目的な設定が搭載されていたが、AIエージェントのコンテキスト混同や「お題目・標語（1回1修正、最大3回など）」の形骸化を招き、実際にはテスト不適合時に同じエラーを何度も繰り返したり、一足飛びに上位の構造変更へと暴走する問題（迷走バグ）が発生した。
  - 原因は、「注意する」「心がける」といった形容詞・推奨ベースの指示は、実行時のAIにとって何ら強制力を持たず、無視して元の慣性（ゾンビ修正）に流されるためである。

- **解決策となぜそうしたか**:
  - `fix-guard` 設定およびフォルダを物理的に完全削除（5Sの整理）し、コンテキストの汚染源を根絶。
  - 代わりに、AIが「特定のツール（コード変更）を実行する前に、必ず特定の検証・仮説ファイルを物理出力（`write_to_file`）しなければならない」という**【物理的アクションゲート】**をすべてのスキルに搭載した。
  - なぜそうしたか：思考のみでは流されるAIに対して、「ファイルの作成・追記」という物理的な外部コマンドステップを挟ませることで、強制的にその論理モデルを脳内にロードし、行動を完全に拘束するため。

- **機械的ルールへの落とし込み (No-Slogan)**:
  1. **`hypothesis-driven-editor` の確立**:
     - コードおよびファイルを変更・作成する前に `tasks/hypothesis_log.md` の物理作成・追記を強制（Hypothesis Gate）。
     - 🟢レイヤー1が完全に枯渇（ログで証明）するまで、🟡レイヤー2に移行することを「手続きアルゴリズム」として絶対禁止。
  2. **`task-tdd-expert` へのWeb検索ゲート搭載**:
     - 具体的な実装前に `search_web` を最低1回以上実行し、得られたクエリ・公式ドキュメントURL・採用知見を `tasks/` ログに物理記録しなければ、実際のコード編集を一切開始できない仕組みを定義。
  3. **`ux-designer` へのUI検証ゲート搭載**:
     - UI変更前に `tasks/ui_design_validation.md` の出力を強制。プレーンな値の直書きを100%禁止（CSS変数の強制）、ARIA必須化、非同期操作のdisabledガード、破壊操作の二重確認ガードを機械的ルールとして定義。
  4. **`python-polars-expert` へのコード品質ゲート搭載**:
     - `tasks/python_quality_validation.md` の出力を強制。1関数最大30行制限（単一責任）、PolarsのLazyメソッドチェーン強制（pandas代入禁止）、型ヒント100%義務化、`uv` パッケージ管理を定義。
  5. **`quality-guard` へのPDCA・5S物理完了ゲート搭載**:
     - タスク開始前の `quality/risks.md`（リスク分析）出力、`git status` に基づく未追跡ファイルの物理クリーンアップ、大規模処理前後の物理リソース監視、タスク完了時のデバッグ物完全消去（`Remove-Item -Force`）を義務化。
  6. **`self-evolution` への自己進化ゲート搭載**:
     - 完了報告送信の直前に、必ず [references/evolution_log.md](references/evolution_log.md) または [references/pattern-catalog.md](references/pattern-catalog.md) に今回の知見を「No-Slogan」の機械的ルールの形で物理追記（`write_to_file`）することを義務化。

### [進化記録] 2026/10/20: 「獲得のみの肥大化（小説家のパラドックス）」を突破する決定論的オラクル＆`ddmin`自動枝刈り（Auto-Pruning）の統合

- **現象と原因**:
  - `self-evolution` によって不適合のたびに機械的ルールや `SKILL` / `HOOK` を追加（獲得）し続けると、モデルの世代交代後に「旧モデル向けの思考手順強制（`HOW_TO` SKILL）」が新モデルの推論能力を逆に阻害する**負の相互作用（Over-constraining）**とコンテキスト浪費を引き起こす。
  - さらに、LLM自身に「このSKILLはもう不要か？」と自己言及（メタ認知）させると、賢いモデルほど「念のため残すべき」と保守的なハルシネーションを返すため、プロンプトの自律的ダイエットが不可能であった。

- **解決策となぜそうしたか**:
  - **役割の完全分離**: LLMにはタスク推論のみを行わせ、SKILL/HOOKの要否判定は外部の決定論的オラクル（Pydantic Schema、正規表現、Python AST静的解析、Pytest）のみが下す `auto_skill_pruner` エンジンを構築した。
  - **なぜそうしたか**: 主観的評価を排除し、「抜いてみて、既存の通過テストケースが1つも退行せず（パレート非退行）、通過率が維持・向上したなら問答無用で削除する」という物理的挙動のみを基準にすることで、有害化した旧SKILLの除去とベースライン精度の単調増加を同時に達成するため。

- **機械的ルールへの落とし込み (No-Slogan)**:
  1. **`HOW_TO` 優先アブレーションとベースライン上方修正**:
     - `HOW_TO`（思考手順の強制）かつトークン消費量の大きい要素をリストの先頭にソートして優先的に無効化テストを行う。削除によってスコアが向上した場合は即座に `baseline_score` を上方修正する。
  2. **Zeller の `ddmin` チャンク枝刈りとパレート非退行条件**:
     - 分割数 $n=2$（前半50%・後半50%）から補集合検証を開始し、塊ごと削除可能なら $O(\log N)$ で一括廃棄する。その際、チャンク内の平均スコア相殺（テストAが直りテストBが壊れる退行）を防ぐため、`baseline.passed_case_ids.issubset(trial.passed_case_ids)` を必須条件とする。
  3. **HOOK の自然死（Natural Death）機械削除**:
     - 本番推論の直近 $N$ 回（スライディングウィンドウ）で `except` 補正ロジックの発火回数が `0` になった HOOK は、テストを回す前に機械的に削除・アーカイブする。
