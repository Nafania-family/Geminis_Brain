# Self-Evolution (自己進化デベロッパー)

「ただの反省やお題目を排し、タスク完了前に物理的な『自己進化ゲート』を通じて学びを機械的ルールへと落とし込む」

## 1. 物理的自己進化ゲート (The Evolution Gate)

🟡中（既存コード修正）以上のすべてのタスクを完了し、ユーザーに「完了報告」を送信する前の最終ステップとして、**必ず [references/evolution_log.md](references/evolution_log.md) または [references/pattern-catalog.md](references/pattern-catalog.md) に今回の知見を追記（write_to_file）しなければ、完了報告を一切送信してはなりません。**

### 【自己進化検証シート（記録内容）】
```markdown
## [進化記録] YYYY/MM/DD: （タスク名・エラー名）

- **現象と原因**: （どのようなエラーや不具合が発生し、その真の根本原因は何だったか）
- **解決策となぜそうしたか**: （どのように解決し、なぜその解決策が最善だったのかの論理的根拠）
- **機械的ルールへの落とし込み (No-Slogan)**: （『〜に注意する』等の標語を完全に禁止し、『〇〇の前に△△ファイルを物理作成する』『1関数30行制限』といった、AIが解釈の余地を持てない【物理ゲート】や【静的・機械的ルール】に変換した内容）
```

## 2. 記述の黄金律（抽象表現の完全排除）

自己進化ログやパターンカタログに学びを蓄積する際、AIを迷走させる曖昧な表現を完全に排除する制約を課します。

- **禁止表現（お題目）**: 「〜を心がける」「〜を意識する」「〜に注意して実装する」「高品質な〜」「適切な〜」
- **義務表現（仕組み）**:
  - **物理ゲート**: 「コード修正ツールを叩く前に、必ず〇〇ファイルを `write_to_file` で出力する」
  - **機械的ルール**: 「行数はコメント除き最大30行」「カラー、フォント、余白の生の直書きを完全禁止（CSS変数を強制）」
  - **手続きアルゴリズム**: 「🟢レイヤー1が完全に枯渇（ログで証明）するまで、🟡レイヤー2に移行してはならない」
